0 · Read this first

Why Next.js?

The original is Python (FastAPI) on Render. Vercel is built for Next.js (JavaScript/TypeScript): push to GitHub and it deploys itself. Python on Vercel is harder for a beginner. Next.js gives you the website and the API in one project, so you manage one thing.

Three honest swaps from the spec

Free-tier rules change. Before you start, glance at the pricing pages of Supabase and Vercel. At the time of writing, Supabase pauses free projects after about a week of no activity, and Vercel Hobby is for non-commercial use. A daily cron ping (Phase 11) also keeps Supabase awake.

One-time setup

  1. Install Node.js, Git, VS Code (in that order). Restart the computer.
  2. Open VS Code → menu Terminal → New Terminal. A panel opens at the bottom. This is where you paste commands.
  3. Type node -v and press Enter. A number like v22.x means it worked.
  4. Tell Git who you are: git config --global user.name "Your Name" then git config --global user.email "you@email.com"

The golden prompting rules

  1. One small task per prompt. Never “build the whole system”.
  2. Always paste the spec section the task comes from. Open REPLICA_SPEC.html in a browser, select the section, copy, paste after the prompt.
  3. Say you are a beginner and ask for “full file contents + exact file path”.
  4. If you get an error, paste the whole red text back and say “fix this”.
  5. Save to GitHub after every phase (see below), so you can always go back.

Starter prompt to paste at the beginning of every new AI chat:

I am a complete beginner with no coding experience. I am rebuilding a college treasurer system using Next.js (App Router, TypeScript), Tailwind CSS, Supabase (Postgres + Auth + Storage) and Vercel, in VS Code on Windows. Rules: give me full file contents, tell me the exact file path for each, explain every terminal command in one sentence, never skip steps, and keep each answer to one small task. Ask me before assuming anything.

How to save to GitHub (do this after every phase)

  1. Terminal: git add . → git commit -m "phase 3 done" → git push.
  2. First time only: on github.com click New repository, name it treasurer-vault, keep Private, then copy the 3 commands GitHub shows under “push an existing repository”.

3 · The roadmap, phase by phase

Each phase has: goal → steps → prompt → “done when”. Do them in order. Never skip.

Phase 1 — Create the project spec §14 step 2

  1. In VS Code: File → Open Folder, create a new folder treasurer-vault on your Desktop, open it.
  2. Terminal: npx create-next-app@latest . Answer: TypeScript Yes, ESLint Yes, Tailwind Yes, src/ No, App Router Yes, Turbopack Yes, import alias No.
  3. Run npm run dev, open http://localhost:3000. You should see a Next.js welcome page. Stop with Ctrl+C.
  4. Install helpers: npm i @supabase/supabase-js @supabase/ssr zod @react-pdf/renderer
  5. Push to GitHub (see above).

Done when: the welcome page shows and the code is on GitHub.

4 · Put it online (Vercel)

  1. Make sure everything is pushed to GitHub.
  2. vercel.com → Add New → Project → pick treasurer-vault → Import.
  3. Open Environment Variables and add the same 4 names/values from your .env.local.
  4. Click Deploy. After about a minute you get a .vercel.app link.
  5. Supabase → Authentication → URL Configuration → set Site URL to that link.
  6. From now on, every git push redeploys automatically.
Common errors & what to say to the AI
  • Build failed on Vercel: open the red log, copy it all, paste with “fix this Next.js build error”.
  • Works locally, 500 online: an environment variable is missing in Vercel.
  • “relation does not exist”: the SQL from Phase 2 was not run fully.
  • Nothing shows for a user: check their role in profiles.
